# 执行、验收与错误积累

## 从审查到实际修改

先按任务范围选择：仅研究/文档无需连接编辑器；审查先只读；用户已要求整改则在该范围继续执行。每次现场写入都需要真实对象证据，但不因此重复索要用户已经给过的授权。

1. 读取当前连接和工程/PCB UUID、版本、单位、原点、层 ID。板名、窗口标题只能辅助识别，不足以限定写入目标。
2. 获取与当前板一致的原理图/网表、BOM、器件 UID、封装脚、走线、过孔、铺铜、规则及约束。保存带时间/哈希的修改前证据，不将截图当工程备份。
3. 生成限定对象的差异：位号/UID、前后坐标与旋转、层、预期网络、需修改的线/铜/规则和机械约束。已有锁定对象/用户修改必须保留，冲突明确报告。
4. 验证实际 API 方法、参数单位和能力，先在可恢复副本验证未使用过的写法。沿用项目核验层和单一队列，不开第二个 Bridge，不并发修改。
5. 全板候选和关键通道共同规划后，按电气耦合范围分批实施与独立回读。单相模板可以小批试放；整板重排也可以将三相与共享驱动作为同一限定批次，不能因旧单相已保存就禁止解锁。移动已布线器件时检查所有附属线端、铺铜与网络，不假设接口自动保持连接。
6. 重新铺铜并检查焊盘/过孔网络、孤岛、断颈、约束优先级和 NC。保存后重新读取/导出；若无法完成持久化核验，明确该层证据缺失。

对当前 API 仓库，继续遵循根目录 `AGENTS.md`、`docs/DESIGN-GUIDE.md`、`docs/KNOWN-ISSUES.md`。本 Skill 不依赖这些文件才能给出板级审查；它们仅在使用该工具仓库操作编辑器时提供具体执行限制。

## 超时与未知写入

接口 timeout 或“成功但没有对象”时，停止依赖该结果的新写入。查询任务记录、读取真实对象集合/属性、比较写前 UID/哈希，再决定补做缺少的一次操作。不要自动重复创建、清空对象或声称已经撤销。

当前仓库已有关于窗口标识、迟到结果、未知状态锁释放和回包窗口匹配的待修问题。包装层、Skill 和离线测试都不能把它们变成已解决；恢复前以当前已知问题文件和实际任务状态为依据。

## 原生 DRC 与工程审查分别报告

过孔尺寸的getter可能舍入，线段也可能由编辑器自动合并或在节点处分割。出现与create返回值不符时，先核对原生尺寸、同网同层的完整几何覆盖和保存文件，不重复创建，也不能只放宽容差掩盖实际缺口。铺铜重建接口可能返回另一块对象，必须独立枚举并按pourId对应真实填充；异网孔的反焊盘还要用原生制造层确认。

| 证据层 | 要记录什么 | 不足以证明什么 |
|---|---|---|
| 接口返回 | 请求/窗口/目标、返回值、超时与否 | 不证明对象已出现或保存 |
| 独立回读 | 独立请求得到的 UID、位置、属性、焊盘与网络 | 不证明持久化及制造输出一致 |
| 保存/导出 | 保存结果、重读或重新打开、导出时间和设计版本 | 不证明波形、温升和 EMC |
| 图面/制造层 | 正确单位、层/镜像、丝印、实际铜形和装配关系 | 截图不能覆盖隐藏网错、孔铜和负载条件 |
| 原生 DRC | 规则集、运行状态、错误/警告、未连接、铺铜状态、豁免范围 | DRC 通过不证明换流、采样时序和热设计合格 |
| 独立工程检查 | 回路、Kelvin、应力、热、机械的逐项证据 | 估算/仿真不代表样板实测 |
| 样板验证 | 工况、探头、原始波形、测点、温度、版本、结论 | 一个轻载点不能支持最大连续/峰值额定 |

DRC API 异常时记录异常及客户端/Gateway/方法版本，检查原生界面或有效导出中能取得的真实结果。独立检查可继续，但不得伪造“DRC 0 错误”或隐藏未运行状态。不同版本的规则/区域 API 需要能力确认。[嘉立创设计规则](https://prodocs.lceda.cn/cn/pcb/design-design-rule/)、[约束区域](https://prodocs.lceda.cn/cn/pcb/place-constraint-region/)

## 工程问题表模板

| 编号/级别 | 位号·焊盘·网络·层/区域 | 观察与证据 | 电气/热/机械影响 | 最小必要修改 | 验证与状态 |
|---|---|---|---|---|---|
| PWR-001/P1 | 填真实对象 | 填图面/网表/几何/数据手册证据 | 解释触发条件，不只写“布局不好” | 写具体移动、重连或规则修正 | 未查/确认问题/已修改待核验/已核验/不适用 |

级别按后果与发生条件决定：P0 用于已确认的严重错误（例如母线硬短）；P1 用于可能导致失效或主要功能不可靠的确认问题；P2 用于一般改进。证据不足单列“待确认”，不要通过提高级别把猜测伪装成事实。

布局整改需要“前后实际变化”，包括关键回路标注和最差瓶颈，不只列操作次数。标签、丝印与位号需在正常视图和输出中不遮挡焊盘、极性或检修标识；字体单位从现有正常对象读取，不猜比例后批量改大。

同时显示全板功能预留与顶/底安装面，区分已落位、完整局部单元、大件预留、未处理器件。局部包络缩小不能证明整板可布；同层碰撞、跨层孔占用与热/装配投影分别报告。存在狭窄出口不等于完整回路质量通过，具体复盘方法见[布局反思](layout-reflection.md)。

## 样板检查计划（用户进行硬件验证时）

先核对静态短路/供电和默认关断，再在受控电源/限流条件下检查驱动、预充和逐步负载。为每项定义通过条件与停止条件，实际限值来自器件和设计预算。

| 场景 | 重点证据 |
|---|---|
| 驱动开关 | 在 MOS G-S 两端测实际 VGS；VDS/相节点过冲、死区和误导通；探头带宽/共模/参考符合节点条件 |
| 电流链路 | 零点、方向、量程、PWM 边沿恢复和有效采样窗口；对照已知电流 |
| 预充 | 冷启动、残余母线电压、超时、控制复位及重复启动；压差与旁路冲击 |
| 热与载流 | 约定环境和散热装配下的连续稳态、峰值时长/周期；最热点、端子和分流温度 |
| 回灌与异常 | BMS/电源吸收边界、掉电及再生过压，按已准备的受控方案验证 |

高侧 VGS 的参考是该 MOS 源极，不把接地示波器地夹接到浮动相节点。没有合适测试设备/条件时留下明确待测项，不用推测填满验收表。

## 持续记录错误

```text
编号 / 日期 / 对象版本
类型：现场发生、静态确认、第三方报告或待验证推测
现象与定位证据：
已确认原因（未知则明确未知）：
影响范围与实际执行过的操作：
修正与回读/保存/DRC/实测结果：
未完成项：
写入设计指导的防复发规则：
```

保留历史编号与尚未解决的状态。文档新增规则不等于历史实机故障已经修复。

替换封装时，同时核对原理图与PCB的器件/符号/封装关联、采购属性和真实引脚网络。直焊点仍应转入PCB，但不应采购旧插座。新建文字优先用当前客户端支持的原生图元API；写入源码成功不代表新增图元被保留，须逐项回读。临时导入器件清理时连同其焊盘网络映射核查，不根据组件数量独自判定清理完成。

先让离线前置检查明确成功，再单独发出写操作。PowerShell中的外部程序返回非零不会自动阻止下一行命令；必须检查退出码，不能把连续两行命令当成条件执行。发生保存后严格比对失败时，保留操作锁，按确切对象和字段解释客户端的格式归一化，并独立回读网络与原生工程；禁止整体忽略属性、层叠或网络差异来得到PASS。

封装参数还需经过“原生工程持久化→重新加载→制造层”核验：当前会话中的焊盘getter及Gerber一致，仍不能证明实例修改已写入工程。若全工程记录未保存修改，进入准确的工程封装编辑器或使用已验证的库更新入口；先确认其全部引用，避免修改旧板共享封装。矩形圆角按当前客户端的比例语义核算，不能把毫米值换成mil直接填入百分比字段。手焊焊盘用受支持的自定义负锡膏扩展关闭开窗，最终检查GTP/GBP实际无该开口及无相应钻孔，不从负数属性自行推断成功。[官方焊盘说明](https://prodocs.easyeda.com/cn/pcb/place-pad/index.html)、[官方PCB问答](https://prodocs.easyeda.com/en/faq/pcb/)

修正某项测量或判断后，搜索所有当前引用该结论的摘要/手册并同步失效说明；旧源码/原始测量保留版本。尤其不能让一个报告已撤回的过孔示例继续出现在“最终几何审查”中。Skill保存方法，项目反思录保存具体证据和本次操作边界。
