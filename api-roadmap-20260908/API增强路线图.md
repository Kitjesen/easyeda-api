# 嘉立创 API 增强路线图

日期：2026-09-08。状态：调研与静态审查完成；以下新增能力尚未部署。

后续社区扩展调研已纳入 **40 项、8 组**具体开发要求，覆盖本轮检查的五个仓库；逐项来源、补强方式和验收条件见 [社区 MCP 借鉴与完整功能清单](community-reference/社区MCP借鉴与完整功能清单.md)。机器可读待办见 [community-backlog.json](community-reference/community-backlog.json)，另有 [220 条工具入口索引](community-reference/community-tool-index.csv)。这些是待开发要求与调查资料，不是已安装功能。

建议保留现有官方 Skill / Gateway，在现有 `eda-verified` 核验层上增加统一任务管理、结构化 MCP 工具和原理图设计规则。先解决写入是否真正完成，再扩大自动设计能力。

本次阅读官方仓库 Issues、Gateway PR、SDK 问题、社区 MCP 源码以及本地 Bridge/核验层。公开源码只保存为文本，没有运行社区补丁。证据索引见 [evidence-manifest.json](evidence-manifest.json)。本轮端口扫描未取得可用 Bridge 响应，未进行客户端实时能力探测，也未修改原理图。现有版本依据上一轮已完成的升级核验记录。

## 一、现有基础与本次确认的缺口

上一轮已启用客户端 3.2.186、Gateway 1.0.5、Skill/Bridge 1.1.28、ws 8.21.3。本地已有工程/图页 UUID 校验、写前源码快照、独立核验、几何去重、日志和串行文件锁；11 项工具测试、24 项实际保存/网表检查属于上一轮的验收结果，不是本次新功能的测试结果。

| 本次发现 | 证据与后果 | 结论范围 |
|---|---|---|
| `/eda-windows/select` 返回对象使用未定义的 `activeWindowId`；实际变量为 `activeEdaWindowId` | 现用 `bridge-server.mjs:204`。赋值已执行后，构造成功响应会抛异常，可能导致响应与实际选择不一致 | 静态确认的程序错误；本轮未在正在运行的编辑器复现 |
| 固定 30 秒超时会删除等待记录，迟到结果因查不到请求而被丢弃 | `bridge-server.mjs:397`、`:449`；HTTP 等待结束不等于客户端执行终止 | 静态确认；不能据此认定全部历史超时来自同一原因 |
| 核验层在异常后也释放 `operation.lock` | `eda-verified/lib.mjs:94`–`:97`；结合上项，后续操作可能误判已经空闲 | 需要持久化“结果未知”状态；已有不盲目重试规则仍应执行 |
| Bridge 收取结果只核对请求 ID，未比对发送结果的窗口与请求目标窗口 | `bridge-server.mjs:449` 后的处理 | 应增加归属校验；没有证据表明本工程发生过跨窗口伪响应 |
| read 模式仍可承载任意 JavaScript；文件锁仅约束经过本地核验层的调用 | 现有 README 已明确这一边界 | 增加固定操作的结构化入口，并让所有本工具写入走同一队列 |

## 二、按实际收益排序

| 优先级 | 增强功能 | 对我们的直接帮助 | 实施边界与验收 |
|---|---|---|---|
| P0 | 长任务状态与重复请求识别 | 超时后能查“仍执行/结果未知/已返回/已核验”；避免重建同一器件或同一根线 | Bridge 与核验层共同改；迟到结果保留、断线不重发、同一操作 ID 不重复提交；进程重启后未知写入继续阻止后续写入，直到核验恢复 |
| P0 | 窗口选择修复、能力探测与兼容表 | 少出现方法不存在、枚举不对、图页未准备好、重连后打到旧窗口 | 启动记录版本、存在的方法、来源及实测状态；函数存在仅代表可见，不等于行为通过。每次操作绑定工程/图页/窗口，并在重连后重新定位 |
| P0 | 修改结果的统一验收与失败定位 | 不再把“API 返回成功”当成“图纸已保存正确” | 分别报告实时属性、独立网表、原样工程持久化、图面证据；缺一项则保留该项待验证。错误包含阶段、目标、原因、原始返回和下一步诊断 |
| P1 | 按引脚接线、按位号更换器件 | 接线不用人工拼长串坐标；换 LDO/MOS/电容时同时保留采购绑定和原连接 | 提供显式新旧引脚映射；读取真实引脚接触点；保持位号和 Unique ID，若原生接口改变身份则单独恢复并核验；端子网络差分必须与计划一致 |
| P1 | 紧凑布局与标签防重叠 | 相关器件集中、局部短线、标签不压在元件上，减少长绕线和重复网络字 | 本地几何规划器加编辑器适配；以已确认的局部样式为模板。纯排版的引脚网表零变化，元件/文字/引脚包围框、图框范围和新渲染同时验收 |
| P1 | BOM 与独立电气规则检查 | 自动找出未绑定料号、0805/0603 不符、DNP 配置、悬空/意外并网、供电遗漏 | 真实库记录与图纸比较；参数缺失标“待查”，不得猜采购参数。电气规则按本项目批准的设计约束运行，不能替代规格书/PCB/实测 |
| P2 | 常用电路模块模板 | LDO、CAN 数字端接、双编码器、半桥等可复用，减少重新画错 | 模板含接线、布局、料号候选、验收及适用电压/控制逻辑。复用前检查项目约束；不按功能名自动叠加芯片 |
| P2 | PCB 协作与发布前检查 | 以后检查网表同步、封装、禁布区域和导出物，比只画原理图更完整 | 先验证原理图与 PCB 对应关系；功率回路、采样 Kelvin、散热与间距需要工程规则。自动布线返回成功不等于 PCB 可投产 |

P0 是扩大写入能力的前置条件；P1 是本工程最能感受到的功能提升。

## 三、可借鉴的公开工作

### 1. 长任务补丁：优先评估移植

官方仓库 [Issue #16](https://github.com/easyeda/easyeda-api-skill/issues/16) 提交了保留超时结果、查询任务、窗口归属校验等改动；配套 [Gateway PR #2](https://github.com/easyeda/eext-run-api-gateway/pull/2) 增加执行阶段和原生错误信息。检索时 PR 仍未合入。

已静态阅读固定提交 `2c0a8a5d805d88a6c96fef8ee71184668afdfded` 的任务模块：它使用内存 Map，限制历史容量，断线记录 unknown。因此它可以作为实现起点，但不能直接满足我们“重启后保留未知写入”的要求；还要补磁盘记录、重复请求识别和原理图写入队列。作者报告的测试结果不是我们的复测结果。源码见 [固定提交](https://github.com/asmoyou/easyeda-api-skill/commit/2c0a8a5d805d88a6c96fef8ee71184668afdfded)。

配套诊断并未解决客户端原生 `clearRouting('all')` 挂起，相关报告明确保留该问题。不能许诺所有原生调用都能取消，也不能制造进度百分比。[SDK Issue #38](https://github.com/easyeda/pro-api-sdk/issues/38)

### 2. 社区 MCP：借鉴结构化工具与能力探测

[Dogmeat88/EasyEDA-MCP](https://github.com/Dogmeat88/EasyEDA-MCP) 的源码包含按器件引脚接网、批量接网、器件修改、文字/导线参数 schema；能力检测代码会检查 `sch_PrimitiveAttribute.createNetLabel` 是否实际存在。可借鉴其工具拆分和类型校验，但本次未安装、未实测整套社区工具。[工具参数源码](https://github.com/Dogmeat88/EasyEDA-MCP/blob/main/src/mcp-tool-schemas.ts)、[能力探测源码](https://github.com/Dogmeat88/EasyEDA-MCP/blob/main/src/bridge-runtime-capabilities.ts)

建议将我们的 MCP 接在现有核验层上，复用唯一 Bridge。不要同时启用第二套独立写入通道，否则现有串行约束容易被绕过。

### 3. 标签与连线问题：做兼容记录和检查，先复现再采用绕行方案

公开报告涉及旧 netport 更新后网络名变空、枚举在 Bridge 上不可用、参数形状与运行时不一致等情况；这些是报告者的环境证据，不代表我们当前每项都必然复现。[Issue #2](https://github.com/easyeda/easyeda-api-skill/issues/2)、[Issue #6](https://github.com/easyeda/easyeda-api-skill/issues/6)

另外，有用户指出符号锚点并非电气接触点，直接比较器件中心/端口坐标会误报悬空。因此接线判定应以实际引脚与导出网表为主，不能把“坐标相等/不等”当成电气结论，也不能把某个报告的短接线绕行方案推广为所有符号的硬规则。[Issue #9](https://github.com/easyeda/easyeda-api-skill/issues/9)

官方仓库仍有开放原理图 group 接口的请求。我们可先维护本地模块成员清单，实现整体移动，但不能宣称已获得客户端原生分组能力。[Issue #1](https://github.com/easyeda/easyeda-api-skill/issues/1)

## 四、建议的结构与操作接口

```text
Codex
  ↓ 固定参数的 MCP 工具
计划 / 实际差异预览 / 能力与版本适配
  ↓
eda-verified：工程约束、任务记录、核验、恢复
  ↓ 单一写入队列（按窗口串行，并约束工程/图页）
现有官方 Bridge + 小范围可追踪补丁
  ↓
官方 Gateway → 嘉立创客户端
```

同一窗口不同图页不能并行写；同一文档若在多个窗口打开也应防止本工具并行修改。工具锁不能锁住用户界面，写前/写后身份与内容差分仍要保留；检测到中途用户修改，应终止后续步骤并重新生成计划。

拟新增 MCP 操作，以下名称是设计提案，不是已经可调用的工具：

| 拟定操作 | 输入重点 | 输出重点 |
|---|---|---|
| `get_capabilities` | 目标连接 | 版本、方法可见性、行为实测状态、兼容限制 |
| `inspect_project` | 工程/页 UUID | 元件、引脚、网络、料号、布局问题、证据来源 |
| `replace_component` | 位号、新 Device、显式引脚映射、源版本 | 修改预览、真实库绑定、身份与引脚网络差分 |
| `connect_pins` | 工程/页、两个实际引脚、目标网络 | 路径候选、意外合网风险、应用后网表 |
| `arrange_module` | 明确成员列表、区域、已确认样式 | 元件/线/标签共同移动方案、碰撞报告、网表零差异 |
| `audit_bom` | 工程、装配方案 | 缺料号、真实封装不符、DNP 与 BOM/PCB 属性不一致 |
| `check_design` | 工程、已批准规则集 | 官方 DRC 原始结果、独立检查、未覆盖项分别列出 |
| `apply_plan` / `get_operation` | 计划哈希、操作 ID、前置内容哈希 | 排队/执行/结果未知/验证状态、原样导出、失败阶段 |

读取类工具不接受任意 JavaScript。开发调试入口单独保留，不能用“只读”的名字暗示任意脚本被沙箱限制。

### 任务状态和恢复约定

1. 提交前落盘 operation ID、工程/页、目标对象、代码/计划哈希及备份索引，再交给 Bridge。
2. 重复 operation ID 且计划相同，返回现有任务；相同 ID 对应不同计划则拒绝。此措施降低重复提交，不能保证客户端跨崩溃的严格一次执行。
3. 超时标记结果未知/仍等待，不认定失败，不解除对冲突写入的限制；只读诊断也不能绕过正在占用原生执行器的任务。
4. 原生返回后进入核验；独立读取和原样工程导出确认后才能标记 verified。returned 和 verified 分开。
5. Bridge/客户端重启后，对未完成记录保留未知状态，重新定位工程、检查结果并恢复；不能自动重新执行写入。
6. 不承诺原子事务、可靠取消或自动回滚。恢复操作要基于新读取的图纸生成差异计划，避免覆盖用户中途修改；已有完整 epro2 备份是恢复依据之一。

## 五、把之前的设计错误变成可执行规则

- 排版：元件、引脚文字、位号、值、网络字均计入布局范围；字号来自已确认图纸样式。模块内短正交线，必要跨模块端口放在留白的短引线末端；不得用缩小字体、藏字或移到远处遮掩重叠。
- 几何整理：删除零长度/重复线段前检查支路与结点；合并共线段不得改变交点语义。移动必须覆盖引脚子属性与 NC 标记，并检查导出中的坐标。
- 电气：通过网表识别真正悬空或意外并网。0Ω、DNP 和可控开关不能一律视为永久短路；分别处理逻辑网络与装配后的导通路径。
- 物料：同时核对供应商 ID、MPN、真实 Device/Footprint、参数和 BOM/PCB 使能。库存/价格若能通过授权数据源取得，应附时间和数量阶梯，未取得时留空，不能用旧价格冒充现价。
- 项目约束：14S/58.8V 仅作用于相关母线节点；栅极、5V、3.3V 等节点按各自额定与瞬态条件分析，不能一刀切按母线耐压筛全板。
- DRC：布尔、汇总数组、明细数组、异常分别记录。warn:3 是汇总结果，不自动转换成 3 个已定位元件。官方检查每个验收周期按需要执行，不无意义反复触发。
- 输出：原样工程、网表和图面版本一致；检查图片非透明、内容新鲜度和导出失败。网表通过不意味着视觉验收通过。
- 错误日志：自动记录失败请求、目标、前后状态和证据路径；根因未证实时写“待确认”。历史未完成项与新发现分开，完成需关联核验证据。

## 六、落地顺序与验收样本

第一批：修窗口选择变量错误；实现长任务与未知结果记录；将核验层状态接入同一任务 ID；增加版本/方法能力清单。先离线/模拟客户端验证迟到结果、断线、重复提交、错误窗口、进程重启，再用隔离测试工程验证普通读写及原样保存。

第二批：新增结构化 MCP、按引脚接线、器件替换和 BOM 核对。先在副本上测试“12 个阻容绑定料号”“0805/0603 封装纠正”“保留旧器件身份替换”这类已知问题，再转入当前工程。

第三批：模块整理、标签碰撞检测、规则检查与模板。用既有 CAN 或编码器区域作为样本：所有既有引脚网表不变、物料不变、无新增重叠、无残留长绕线，并取得新版实际图面。随后再扩展到 PCB 协作。

当前 Driver 封装、部分注释、临时导入器件与 DRC 待办仍按既有修订记录处理，本路线图没有将它们标为完成。

## 七、客户端限制

新版 `SCH_Net` 文档标注 v4.2 新增，不能因为 Skill 已升级就假设 3.2.186 可用；能力不足时仍走完整网表导出。官方 DRC 明细、原生分组、后台渲染以及 PCB 原生清线挂起，都不能由 MCP 外壳直接补齐。[官方 SCH_Net 文档](https://github.com/easyeda/easyeda-api-skill/blob/8895d98637dab59ed9de10bb2a340e3e4be26d99/references/classes/SCH_Net.md)

本次交付为路线图、公开来源快照和错误/设计指导补充，没有部署第二个 Bridge、社区 Gateway 或新增 MCP 服务。
