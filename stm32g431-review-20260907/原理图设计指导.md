# 原理图设计与审核指导

适用对象：本 STM32G431 工程；2026-09-07 初版。继承此前用户要求：相关元件紧凑分组、短而明确的连接、标签不压线不压元件，并持续记录错误。

## 工程识别与证据

1. 操作前校验项目 UUID、图页 UUID 与主控型号。新旧工程分别保存报告与证据。
2. 页切换、读取、写入、验证按依赖顺序执行；不并行处理同一画布状态。
3. 一次读取的开始与结束校验当前页；当前页变动即丢弃该读取。修改后重新读取网表、器件属性和图面；三者通过才称修改完成。
4. 导出检查实际格式，PDF 逐页查看。DRC 只返回汇总时明确保留未检查的明细，不能报告全部通过。

## 元件与电气参数

1. 电容审核同时查网络实际电压、绑定料号耐压、直流偏压后有效容量、纹波电流与温度；显示“22µF”不等于物料规格正确。
2. LDO 按所有下游负载核算损耗及最坏环境温度，核对厂家对输出电容类型/ESR的要求；不因相同“1117”名称就互换稳定性规则。
3. 开关节点 RC 吸收先估计 C×V²×f 损耗，再依据实测振铃定值；不得复制去耦电容数值。
4. TVS 比较工作电压、击穿和指定浪涌下的最大钳位；不能把料号里的电压当作被保护电压。
5. MCU 外设按准确型号与封装的 AF 表核验；网络名为 SPI 或 PWM 不是硬件功能成立的证据。
6. 电流传感器的采样路径、有效开关状态、ADC 窗口、延迟和量程必须一起定义。
7. “过流保护”必须能沿图追踪到检测阈值、关断动作和异常状态；单一 GPIO 控制开关仅是执行部分。优先使用现有 MCU 内部比较器/定时器刹车资源，避免无依据增加芯片。
8. 电源磁珠通常不能替代合理的地回流设计；功率地与逻辑地的连接必须结合 PCB 验证。

## 图面与标签

1. 按信号从左到右、电源在上、地在下组织功能块；外围元件靠近所属引脚，三相使用一致行列、方向和间距。
2. 同一功能块优先短实线连接；跨块使用成对明确网络名。避免跨整个图的地线、绕框长线和重复网络标签。
3. 标签放在引线端的留白处，先算文字占用范围，再安排间距；不得压符号、位号、数值、结点或相邻网络。
4. 字号只使用经过单个对象试改并重新读取验证的单位与数值；不能大批量猜测字体单位。保持常规缩放下可读且不遮挡。
5. 移动元件时同时处理连线与相关文字；检查交叉是否有结点、悬空端点、被折线绕接造成的误连。按功能块导出局部视图自查，再查看全页。
6. 标注有电气含义：如 VCC 实为高压母线，应改用更明确的名称并全网核验；不能把“上桥臂支路电流”无条件标成“连续相电流”。

## 完成标准

- 原理图连接、绑定 BOM、物料规格、显示标签一致；NC/DNP 与装配状态一致。
- 修改前后有快照；每条问题有稳定编号和验证证据，未测量的项目保持待验证。
- 原理图审查、PCB 审查、固件时序和台架测试分别说明范围；不能从任一项推导全部完成。

## 2026-09-07 实际修改后补充

### 本 Bridge 版本的可靠写入方法

1. 修改前导出完整 epro2，并锁定当前工程和图页 UUID。保存旧位号、Unique ID、引脚位置、所有相关线段和物料属性。
2. 更换物料从 LCSC 精确料号获取库器件，并在最终坐标创建。读取真实引脚坐标、封装和供应商料号后，逐个修改属性图元；避免 component.modify 导致关联损坏。
3. 图元 API 接收 ID 与对象时，不假定两条路径行为相同。当前环境已实测：属性位置修改宜传对象；BEAD3 删除用对象才落图；多段导线 modify 仍可能无效。必须以回读结果选择可行路径。
4. 多段导线按每 4 个数字拆成一段，不能按连续折线解释。需要重建时先完整保存分支，删除指定组，再逐段创建；端点坐标取合理精度，不生成零长度线或重复段。
5. 参数对象和网络标签的修改分别检查。网络文字看对了，还要确认实际 wire.net 以及器件 pinInfoMap；跨页网络必须核验两端。
6. 单次调用只完成一个能够检查的功能块。修改后另起读取，确认 source、有效网表及导出 PDF；缓存滞后时先二次回读，不重复创建。脚本的 `{error}` 必须传递成外层失败。
7. 最终检查无临时位号、无重复 Unique ID、替换件关联完整、旧件确实消失；比较未计划修改的引脚连接分组，检测误删/误接。工程导出也要验证实际器件和线网已持久化。

### 版面验收的具体要求

- 元件外围靠近所属引脚，但必须为位号和数值各留一行空间。电阻数值与相邻电容位号不能合成一串文字；用错行、左右对齐和短引线解决拥挤。
- 网络标签离引脚号码、结点和边框留出间距。相线标签放在端口留白处，不压在传感器 IP 引脚上；一个功能块内部保持紧凑实线，跨块才使用同名端口。
- 图框内同时容纳符号、标签、位号、数值和电源旗标，不只检查元件中心。新增旁路的电源旗标不得跨图框。
- 对多个相同 ESD 器件，可保留各自位号，统一写型号说明；BOM 中仍保留每个器件的准确关联。
- 删除支路后，检查其上/下游是否残留短线或单端器件。多段组改动要检查所有交点与分支，不能只看删除对象本身。
- PDF 全页看结构，局部放大看标签与接线；两者均需要。文档里计划的位置不能作为版面通过证据。

### 工程结论必须保留的边界

- 优先用最少且能验证的功能块解决问题；先定义电流阈值、故障响应和复位行为，再决定内部比较器或外部芯片，不按“保护功能数”逐个堆芯片。
- LDO 改为支持陶瓷电容的型号只解决兼容性依据，不能代替有效容量、低温和热验证。ADC 理想满量程不是母线允许电压；电流传感器量程不是板子额定电流。
- 相线位置正确不等于共模瞬态性能已验证。TVS、BMS、回灌和预充属于同一电源边界，不能把栅极缓变或 MCU 开关等同为有压差判据和超时的预充。
- 首轮审核保持历史快照；修改后另写修订状态，不将历史“待整改”直接当成当前结果。固件与 PCB 未改时必须明确注明。

当前成果与未完成项：[修订记录](STM32G431原理图修订记录-20260907.md)。

导出和关闭重开须单独检查：本轮旧 TEXT 在当前 live/get 中消失，但 PDF/epro2 和关闭重开后仍存在。最终用官方源码接口限定移除唯一旧 TEXT，并验证网表不变、重开后不再出现，再重新导出。不得用清理导出副本代替修复应用持久化状态。源码接口必须使用刚读取的当前页、已有完整备份和严格的目标记录断言，不顺带修改电气连接；未完成项不能因导出文件能打开就改为“已完成”。

## 2026-09-07：机器人 LDO 对标补充

1. 参考他人设计必须记录实际项目、版本、器件位号和精确 MPN；系列名不补造采购后缀，BOM 不单独证明并装关系，不将模块厂商设计混称为原厂所有版本。
2. 对标是候选依据，不能替代本板负载/环境分析。300mA 小封装未必能在 5V→3.3V、250mA 和高环境温度下工作；1.2A 大额定也不意味着能忽略约 0.45W 发热。
3. LDO 的输入与输出去耦应就近回到自身地参考。GND/PGND 单点桥放在局部去耦回路之外，并在图上显示两个网络名称；“经 0Ω 直流导通”和“高频回流布置合理”分开判断。
4. 本板 U9 现为 LDL1117S33R/C435835；1 脚 GND、3 脚 +5V、2/4 脚与散热焊片 3.3V。散热铜皮不能接成 GND。输出为 C39 22µF/25V 加 C42 100nF，C40 已删；台架仍须验证有效电容和瞬态稳定。
5. 密排电容优先将外侧电容的位号/值放在外侧留白，不能放到相邻电容本体上；电阻的两行文字不要跨本体或公共地线。标签属性的 API 调用成功不等于对齐生效，源码和新渲染都应核对。
6. 复用同引脚功能的符号必须保留真实 Device 与 Footprint 绑定；新旧符号坐标不同先查全部引脚。启用 BOM/转 PCB 后再恢复 Unique ID，避免自动编号覆盖。
7. 完整工程、网表、画布、PDF 分别标注证据状态。抓图需检查非透明/非旧帧；本轮 PDF 超时，不能沿用旧 PDF 声称新版视觉检查已完成。

## 2026-09-07 CAN 数字端接与 API 操作补充

1. 端接是跨 CANH/CANL 的可选支路，不要把控制开关串入主通信路径。主干线仅两端接入；复位/断电状态、首次配置和固定端点必须一起设计。
2. 对浮动差分网络使用双向开关，计算其导通电阻、关断电容、驱动条件及耐压。不要使用单个带体二极管的 MOS 或未经共模范围核验的普通低压模拟开关。
3. 强制端接的选配 0Ω 只跨接开关输出；明确默认 DNP、BOM 不装但 PCB 留焊盘，以及安装后软件无法断开。
4. MCU 引脚分配核对整个工程的位号和功能占用；去除该脚 NC 后接线。新件先验证实际引脚和库绑定，再替换旧件；装配属性与第一次保存可能触发自动 Unique ID 分配，最终在独立步骤恢复旧件身份。
5. 模块内部优先匿名短实线，跨块才用必要标签。当前版本可能在保存/导入时把 NET 的 valueVisible=false 恢复成 true；应删除冗余 NET 属性，并通过网表核验真实连接。不要把文字挪到远处、改成白色或缩成不可读来掩盖。
6. 整体平移同时覆盖元件、所属标签、线组各独立 LINE、旗标和注释。以实际图框坐标为准；本页编码器区域下边界是 y=190，不能根据截图比例猜成 215。
7. EPRU 最后一条记录可能没有末尾竖线；转换源码必须逐条保留原分隔符和换行。完整工程还可能包含空体的删除记录，解析和比较时须保留，不能视为损坏文件或当成活动图元。
8. 写入一次后从独立调用核验；缓存不一致时仅重试读取。先判断实际已存在的段，再恢复缺失段。不得因立即 get() 看不到就重复添加。
9. 优先使用 [本地核验工具层](../eda-verified/README.md)：自动发现桥接、串行锁、工程/图页双重检查、快照、错误传播和核验日志。它不是事务或自动回滚，也不能保证编辑器后台渲染。
10. 电气验证、坐标/标签验证、工程持久化、实际图面和台架测试分别记录。操作核验脚本应包含新增可见标签数量，防止仅网表通过就漏掉图面问题。

本轮实现及后续固件/装配约定见 [CAN 数字端接设计与修订](CAN数字端接设计与修订-20260907.md)。

## 2026-09-07 双编码器审查补充

1. 先核验供电模式、TEST、共享 SPI 与独立片选，再判断外围是否应改；同名引脚不能替代有效网表检查。
2. 检查启动、复位和高阻阶段的数字输入电平。共享 SCK/MOSI 的外部弱下拉可设在公共网络，各支路通过已装串阻获得偏置，不必重复堆叠。
3. 串联阻尼电阻没有通用最优值。按驱动端、实际拓扑、走线和波形定值；不能把 100Ω 自动判错或批量改成更小数值。
4. 两颗编码器的电气存在不等于机械上可测两轴；确认各自磁体、安装位置和板间连接。分辨率、绝对精度、动态延迟、磁干扰分别核验。
5. 将通用未绑定阻容明确列为 BOM 待定，不把图纸显示值当作采购闭合。读图、网表、PCB、固件、台架状态分别记录。

本轮只读结论与建议：[双编码器电路审查](双编码器电路审查-20260907.md)。建议的小改尚未写入原理图。

## 2026-09-08 双编码器实际修订补充

1. 相同 0603 封装的库符号也可能有不同引脚间距，本次 1µF 符号为 30 单位，旧符号为 40。放置后读取端点，再调整短引线；不能依据旋转角或器件中心判断已连接。
2. 器件移动涉及子引脚属性：NO_CONNECT 的 parentId 可能是“组件 ID-引脚 ID”，只移动直属 ATTR 会遗漏其持久化坐标。独立核对图页源码和 epro2；必要时用正式引脚 API 清除再重新生成标记，不能放宽比较忽略错误。
3. 电容标签拥挤应调整局部元件间距和供电回路，保留正常字号；优先局部电源、地旗标，避免围绕整个芯片的长地线。
4. 核验失败时工具层保留日志，可能不生成成功输出文件；从已报告的日志目录与实时工程继续，不猜测文件存在。阶段计划完成后不要重跑。

已实施的物料、接线和布局见 [双编码器修订](双编码器物料与接线修订-20260908.md)。

## 2026-09-08：客户端版本与 DRC 验收

1. 升级前确认官方公开发行版、安装器签名和本机实际版本。API 文档的“某版本新增”不能用作该版本已发布的证据。本轮可下载并已安装的是 3.2.186，未查到 4.2 官方公开安装包。
2. 完整导出当前工程后再升级；保留原样 epro2、散列和安装日志。安装到原目录，禁止无备份卸载工程数据；升级后重新发现 Bridge 窗口和目标项目/图页，回读版本、网表及完整工程。
3. DRC 调用成功、返回汇总、取得明细、清零设计问题是四个不同状态。3.2.186 本次仍只有 warn:3 汇总；不能以通信正常替代规则验收。
4. 供应商标准化同时核对料号、完整制造商型号、采购值和真实封装。库导入后 UUID 可以变化，不能据此认定错误；0805 采购件绑定 R0603 则是必须修复的实际错误。
5. 位号遵循器件编号规则，端子用途另以网络名或局部注释表达。电容耐压、选配 DNP 等工程说明不要挤入用于标准化比较的名称，应保留明确、就近且不重叠的独立文字。
6. Text API 的数字枚举与源码中的对齐字符串不同，独立文字内容在 TEXT.value。创建返回 undefined 即未确认成功；从新 source 和原样导出验证文字存在，不用期望计划替代实际图面。
7. 用户中断时记录已应用与未应用的步骤。升级只验证原状态保留，不自动把旧待办标记为完成；临时封装导入器件必须单列待清理，不能流入正式 BOM 或 PCB。

1. 超时后仍可能有客户端执行，不能根据 pendingRequests=0 或文件锁已释放就认定空闲。任务持久化机制尚未实施前，继续遵守写入不盲目重试、先核查真实状态的约定。
2. 能力分为“文档存在、运行时方法可见、行为已验证”三个层次；特别是标注 v4.2 的 SCH_Net 与 DRC 明细，不推定当前 3.2.186 支持。
3. 下一版工具应使用实际引脚和网络进行接线，不以器件/端口中心坐标相同与否判定导通；符号锚点与电气接触点必须区分。
4. 纯排版必须保持引脚网表不变，连同位号、值、标签、子引脚 NC 属性一起规划，并通过原样导出和实际新图面验收；外部社区工具有排版或接网入口不等于已经满足本工程约束。
5. 模块化 MCP 复用现有核验层与唯一 Bridge。不得在未接入同一写入队列的情况下增加另一套自动修改通道；不能把恢复流程宣传为原子事务、可靠取消或自动回滚。

具体待实施能力、顺序和验收见 [API 增强路线图](../api-roadmap-20260908/API增强路线图.md)。本轮只完成调研与文档补充，没有将拟定工具标为已安装。

### 社区 MCP 参考的进一步补充

- 已收录 [40 项社区借鉴要求](../api-roadmap-20260908/community-reference/社区MCP借鉴与完整功能清单.md)。重点用于本工程的字段和连接真实性、紧凑排版、电源树评估以及后续 PCB 同步；社区的其他 MCU/NE555 样例不直接作为本板设计。
- 排版的电气差分按稳定器件身份与引脚连接集合检查；导线/标签 ID、线段拆合和坐标属于结构差分。不能因合法线段拆合导致单一哈希变化就误报电气改变，也不能仅比较网络名字而漏掉短接。
- 名称推断出的引脚角色只是线索；库 pinType 未定义时保留未知，回查数据手册。备选料封装匹配和库存评分也不能替代电气兼容判断。
- LDO、电源树和 SPICE 工具要记录负载、输入范围、热阻、环境温度、器件模型及缺失参数。计算通过不替代本板 PCB、热和瞬态实测；14S 要求只施加到相关电源域。
- 原理图与 PCB 同步前先列 Unique ID、封装、焊盘网络和仅 PCB 器件差异。元件替换不能仅保留位号而丢失原有身份；同步返回成功后仍独立核查。
- 本地渲染预览与编辑器原生截图分开标注；导出包分别检查真实文件的工程来源、时间、哈希、必需层和 BOM/CPL 对应关系，不仅检查声明的元数据。
