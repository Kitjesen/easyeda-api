# API 与原理图设计指导

本文件约束后续工具实现，来自当前协作中出现过的问题；详细历史见 [原理图设计指导](../stm32g431-review-20260907/原理图设计指导.md)。

PCB 工作需同时阅读 [PCB 专题](../pcb-knowledge/README.md) 和 [PCB 设计指导](../pcb-knowledge/PCB-DESIGN-GUIDE.md)，以功率回路、真实机械/制造条件和实际器件为约束。仅靠原理图排版规则或通用自动布线参数不足以完成电机板设计。

## 一次修改的完整流程

1. 读取唯一窗口、工程 UUID、图页 UUID、实际 API 能力。记录当前版本和原始图面。
2. 取得真实器件身份、封装、引脚坐标和网表。把期望连接写成引脚到网络的表，保留明确 NC。
3. 生成限定对象范围的计划及源码哈希。保留 Device、Unique ID、位号、采购料号和 PCB 关联。
4. 先计算紧凑布局和短实线，检查端点、标签外框、重复段和交叉点。模块之间用必要的标签/端口。
5. 经同一入口写入一次；执行状态未知时停止新的依赖写入，读取现场确认。禁止按超时次数重复创建。
6. 用独立请求检查实际属性和引脚网络，再保存、重新读取/导出，检查正常字号图面。分别记录官方 DRC 与独立检查。

## 图面规则

- 同一芯片的阻容、钳位、上拉下拉围绕对应引脚成组；去耦和反馈回路近邻排列。
- 信号通常从左到右，电源在上、地在下。先定器件位置，再生成正交短线；不以长线把散落器件串起来。
- 标签的方向、锚点和外框须避让器件主体、位号、参数、引脚和相邻标签。字号/单位从当前图页的正常实例读取，不猜缩放比例。
- 模块内部能清楚直连时用短实线。删除完全重复、零长和无意义折返线；不能仅因交叉看似重合就认定相连。
- 同一类三相或双编码器模块使用一致间距与方向；先调整一个模块并验证，再推广。
- 排版修改前后比较引脚连接集合，避免删标签后改网名或意外短接。截图好看不等于网表正确。

## 防止设计过度复杂

先把需求列成必要功能和故障行为，再确定每个器件的职责。预充的驱动、限流、母线压差判定和超时状态机分别有明确承担者；LTC7001 是高侧栅极驱动器，不能仅凭单芯片名称假设已具备全部判断逻辑。可由 MCU 承担的逻辑应评估上电默认态、失控条件与必要硬件保护后精简。增加器件需说明可验证的用途。

## 版本、证据和错误积累

上游客户端、Gateway、Bridge/Skill、包依赖和本地补丁分别记录版本。社区代码按固定提交读取；先做适配测试，再进行隔离工程实测。每个新错误追加 [错误记录](ERROR-LOG.md)，含现象、确认原因、影响范围、修正、验证、未完成项。不要把调研项批量改为已完成。
