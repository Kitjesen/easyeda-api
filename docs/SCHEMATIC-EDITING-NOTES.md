# 原理图排版、写入与验收注意事项

适用于通过 EasyEDA API 调整现有原理图的布局、标签和说明。以下操作现象来自 2026-09-10 的专业版 3.2.186、Gateway 1.0.5、Skill/Bridge 1.1.28 实际使用；它们是该版本的观察，不是所有版本的接口保证。本文不决定器件选型、PCB 布局或整机额定。

## 先排整页，再处理局部

- 用户要求“整体整齐”时，先分配模块面积、阅读顺序、框线和标题位置，再安排元件与走线，最后调整标签。只把重叠文字往旁边推，会留下大块空白与局部拥挤并存的问题。
- 同页采用一致的标题位置、内边距和文字层级。通常把模块标题放在左上角；为标题预留真实空间，不能直接叠到已有电路上。
- 同类电容、三相支路、编码器和双接口按共同基准对齐。双接口成对展示并写明连接关系；外观排列不能替代并联/串联关系的电气定义。
- 位号与数值紧靠元件同一侧成组放置，保持一致的行距和对齐。标签到元件的距离可先取约半个至一个字高；需要移得很远时，优先调整所在侧、元件间距或局部导线。
- 同时检查文字边界、符号、引脚号码、结点和框线。不以“文字中心没碰到导线”或“两个元件中心不重合”作为通过依据。
- 长型号和说明应安排足够空间；不靠缩小到难读的字号、隐藏必要标签或涂白覆盖解决碰撞。说明较多时放入独立备注区，保留其原有含义。
- 字号和线宽先从当前图纸正常实例读取，再用原生渲染确认。本次用 14 的模块标题、9 的备注和 2 的黑框线宽实现统一，但这些是源码单位的案例值，不是通用像素或印刷字号。
- 自动图框的项目名可能溢出，修改实例字体也可能不影响动态渲染。必要时用可编辑的非电气文字重新组织标题栏，保留完整项目信息，并检查实际导出结果；不要直接隐藏信息交差。

## 完整移动一个功能块

移动前为对象建立明确归属；坐标落在同一矩形内不一定意味着属于同一电路。共享参考端、边界线段和电源端口需要单独核对。

一个完整移动组可能包括：

- 元件实例，以及位号、数值、型号和额外说明属性。
- 电源/地端口等没有普通位号的 `COMPONENT`。
- `parentId` 指向“元件 ID-引脚 ID”的子属性，包括 `NO_CONNECT`。
- `WIRE` 组中的每条独立 `LINE`，以及挂在该组上的 `NET` 属性。
- 对应的非电气文字、图框和原有不装区域边界。

先核对每个移动对象只有一个归属，再变换完整组。对线段不要擅自按一条连续折线解释；当前数据中多段路径可能按每四个数字表示一条独立线段。源码修改须保留原换行和末尾分隔符。

平移后检查原来重合的引脚与线端仍然重合；不同线组间的接触关系不能意外增加或减少。局部压紧时还要查导线是否穿过其他网络的引脚，即使网表尚未合并，也不能保留误导性的图面接触。

源码和 API 的坐标方向、对齐枚举不能混用。本次源码负 Y 对应 API 正 Y；推广前用单个已知对象核对，不把该符号转换硬套到其他格式。

## 标签可能改变连接

- `NET`、电源端口的 `Name`、`Global Net Name` 与普通 `TEXT` 不同。显示文字正确不代表网络已经绑定；浮在附近的标签也不等于连接到导线。
- 调整外观时保留电气名称和真实锚点。不能因名字相似就把 GND、PGND 等网络合并。
- 曾观察到把根标签的 `parentId` 改成线组后，编辑器创建了新的绑定属性，却保留旧的悬空标签。要按实际回读识别新 ID、检查父级与重复对象，不能只验证旧 ID。
- 删除或修改返回成功不一定落图。需要核对实时对象、网表和后续原样工程导出；不得反复创建“替代品”堆出重复对象。
- 定位电气差异时比较任务开始基线、紧邻写入前快照和写入后快照。写入前已经存在的改动不能归因于当前标签移动，也不能为了匹配旧坐标而覆盖用户修改。

## 写入、失败和恢复

1. 复用用户已指定的目标窗口；写入前校验实时窗口、项目 UUID、图页 UUID 和文档类型。读取开始与结束的上下文应一致，不能误写参考工程。
2. 先保存完整工程备份，再生成限定对象范围的计划。源码快照只是补充，不能代替完整工程文件。
3. 现场写入保持串行。可并行准备不同图页的离线计划，但只由一个入口切页、写入和核验；下一步依赖实际退出状态，不依赖“调用已经发出”。
4. 一次写入后单独回读。超时、`false`、`Source rejected` 或核验失败都先视为结果未确认，读取实际状态后决定是否需要恢复；不自动整批重放。
5. 本环境出现过编辑器在后台时源写入失败，而恢复目标窗口后同一计划成功。这是状态相关现象，不能据此断定所有拒绝都由后台造成，也不能无证据归咎于许可。
6. 新增多个 `TEXT` 的源码批次曾被拒绝；保留已有对象修改，新增文字改用正式 `sch_PrimitiveText.create` 后成功。使用当前版本真实签名和枚举：本版 `LEFT_TOP` 的枚举值为 `1`，直接传字符串名称并不等价。
7. 若工具报告用户按 Esc 停止电脑操作，按工具要求停止本轮工作，明确报告哪些修改已保存、哪些验证/导出未完成；不要继续后台写图或把中断当成完成。用户随后明确要求继续时，从当前状态恢复。

### 区分显示规范化与真实差异

本次把文字颜色从空值改成黑色时，编辑器会把部分 `fillColor: null` 自动补为 `#000000`；另一些颜色原本已是黑色的文字仍保持空值。完整对象逐字比较因此可能报错。

遇到这种情况先列出实际字段差异，确认只有已观察到的显示规范化，再修正独立核验的预期。不要为让检查通过而忽略所有差异，更不能放宽元件身份、连接名称、锚点或引脚检查。核验器误报时不需要重放已经成功的编辑。

## 电气、持久化与图面分别验收

| 检查 | 要证明的内容 |
|---|---|
| 元件与属性 | 元件集合、位号、Unique ID、Device、Footprint、物料参数及装配状态符合本次范围 |
| 引脚连接 | 比较完整引脚连接分区以及命名网络所含引脚，不能只比较元件数或网名数量 |
| NC | 每个未连接引脚是独立端点；另查正式 `NO_CONNECT` 标记的存在性、所属引脚与最终落点，空网名不能替代标记，也不能把所有空网名合并成一个公共节点 |
| 官方 DRC | 记录实际返回和覆盖范围；空列表不能替代上述独立比较 |
| 原样工程导出 | 保存真实 API 返回文件，确认改动已持久化；仅改原理图时核对 PCB 等未涉及文档 |
| 原生图面 | 全页检查分区、密度和层级，局部放大检查每组标签、引脚和接口归属 |

本次完整 EPRU 导出包含更新和删除记录：按 `DOCHEAD` 分文档，按文件出现顺序逐条处理，以对象 ID 作为状态表的键，应用更新和空 body 删除后再比较有效状态。不能先按 ID 排序；直接汇总所有非空历史行也会把已删除对象重新算进去，产生假的缺件或连接差异。

PDF/图片输出应关联本次调用、新文件及修改时间。确认导出请求完成且返回有效内容后才渲染；超时后不能继续读已有同名旧 PDF 并称其为最新版。全黑、透明或来自其他前台应用的截图也不能用作原理图证据。

原生 PDF 的文字边界与矢量线段相交检查可以辅助找问题，但引脚文字、内置符号、空白字符等会产生误报，须放大确认。不得离线改图来冒充编辑器修复。

最后分别报告：已写入、已回读、已保存、完整导出、图面检查、官方 DRC、独立连接检查。中间版本的检查通过，不能替代最后微调后的验收；这些结果也不证明 PCB、固件或实板已经验证。

## 2026-09-10 补充：换件、重连与增量验证

本节提炼后续模拟地迁移、器件替换和指示灯修改的实际经验。历史错误编号保留在现场记录，API 仓库的可复用摘要记录于 `docs/ERROR-LOG.md` 的 API-018 及后续条目；本节也可独立复制到 Skill 参考目录阅读。

### 真实器件身份与引脚不能靠记忆

1. 从实际器件库查询采购号、厂家、完整型号、封装与当前供应状态，再对照准确型号的原厂资料。相邻采购号、同样的颜色名或通用封装名不证明器件等价。
2. 创建前按全工程检查位号和 Unique ID，而不是只查当前页。使用唯一暂存身份，记录返回的 primitive ID；自动重编号后继续按真实 ID 定位。
3. 在不进入正式 BOM/PCB 的暂存阶段读回真实符号引脚、脚号、坐标和极性，再规划接线。两颗同为 0603 的 LED 也可能一颗为 2 阳/1 阴，另一颗为 1 阳/2 阴；不能沿用旧符号的脚号假设。
4. 保存稳定后核对 Device、Symbol、Footprint、Supplier Part、Manufacturer Part、Value、额定参数和 BOM/PCB 开关。有采购号不代表实例数值已显示，修改显示型号也不代表实际换件。
5. 保留旧 Unique ID 用于 PCB ECO 对照时，另行检查新符号到新焊盘的映射；身份连续不等于焊盘极性兼容。导出可能补齐 Unique ID 或改变记录顺序，定号和装配开关变更后还需最终回读。

云端库导入工程后可能分配项目内 Device/Symbol/Footprint UUID。验证应同时保留原始库查询与原样存档中对应 DEVICE 的来源关系、器件引用和采购属性，核对来源链；不能要求项目内 UUID 与云端 UUID 字面相等，也不能只凭实例上手填的料号认定真实绑定成立。

指示灯还要先定义含义：硬件电源灯独立于固件，明确表示哪条电源轨存在；状态灯明确 GPIO、有效电平、复位/未供电默认态与电流返回。数字指示电流不应随便接入模拟参考支路。颜色更换仍是器件更换，须重新核对目标电流下的 Vf、供电容差、GPIO 电平压降、限流电阻、极性和亮度条件；亮度与启动闪烁保留为实测项。

3.3V 灌电流支路由红灯换蓝灯时，按“颜色要求 → 具体型号及后缀 → 真实库引脚 → 压降预算 → 实测亮度”推进。资料在 5mA 下给出的 Vf 和光强不能直接作为低于 1mA 工作点的保证；用该 Vf 代入限流公式只能得到初步估算。减小电阻可提高有电压余量时的电流，但不会提高供电电压或消除 LED/GPIO 压降。没有明确亮度要求时，先保留可解释的低功耗起点，不因换颜色就盲目降阻或增加驱动管；实际电流、温度/供电容差下可见度、复位状态和 PCB 极性继续验收。

### 重连后重新锁定目标

Bridge 重连后窗口 ID 可能改变，参考工程也可能成为 active。旧 ID 失效时，重新枚举连接并逐窗口核对项目 UUID、图页 UUID 和文档类型，只更新已确认同一目标的本轮明确窗口 ID。不要退回缺省 active，不因守卫拒绝绕过校验，也不要重放其他图页已完成的修改。

请求返回运行中的 session 只说明进程还在运行。必须等到真实退出状态，确认成功及本次输出文件存在，才能启动依赖它的计划生成、下一页写入或导出后处理。PowerShell 的前序非零退出不一定阻止下一条命令，应显式检查 `$LASTEXITCODE` 并在失败时结束依赖步骤。

多操作脚本中后一步失败，不能推断前面也没有修改。独立列出“已改旧对象、已创建对象、缺失对象”，只补确实缺失的部分。正式 `sch_PrimitiveText.create` 也观察到过返回 `undefined`；API-014 中成功使用过的替代方法不构成每次必成功的保证。

### 源码格式、生成脚本与核验器

- 原末条记录可能合法地没有末尾竖线。追加记录后，它变成中间记录，需要补齐中间分隔符；仅“保留原格式”还不够，也不能对所有记录盲目 trim 或统一拼接。
- 离线生成脚本中的字符串转义要按最终执行文本检查。若执行器把内容包在异步函数中，用相同的 `AsyncFunction` 语法上下文做不执行的解析；CommonJS 顶层 `await` 报错不是该执行脚本无效的证据。语法检查之后仍保留源码和对象前置守卫。
- 精确比较被拒时先逐 ID、逐字段解释差异。记录顺序变化可在解析后比较有效记录；自动填充字段只能按已确认的窄范围处理，不能忽略所有元数据或关闭身份/网络校验。
- 导出没有独立内嵌网表时，采用“独立实时全引脚网表 + 原样存档有效实体”的两份证据，说明各自覆盖范围，不能把存档实体重构称作已读取内嵌网表。
- 完整比较时把允许改变的引脚与其余引脚分开。未影响部分比较连接分区及采购身份，正式 NC 各自为独立端点；本次更换带来的新增库文档也须逐份解释，不能将其当成未知差异整体忽略。

### 原生显示限制与导出路径

新增长网名、NC 十字和脚注也要局部放大检查。观察到 NC 属性坐标回读改变，但实际 PDF 中十字没有移动；本版引脚 API 可写编号/NC 状态，号码位置属于符号定义，尚未确认受支持的实例级位置覆盖。无效偏移应恢复，保留可追溯的显示缺口；不画普通十字、不涂白遮盖，也不为修一个实例擅自修改共享符号。

位号和型号应在元件旁成组安排，并给 LED 发光箭头、极性和短线网名留出空间。仅电气检查通过时不能写“全图无重叠”。最终报告需明确正常视图、局部放大、原生渲染各自发现的结果。

复用渲染脚本前先确认路径基准是调用目录、脚本目录还是参数目录。使用本次导出的原始数据解码，核对文件签名、字节数与 SHA256 后再渲染，避免误读历史同名文件。辅助脚本不要命名为 `inspect.py`、`json.py` 等标准库模块名；本次 `inspect.py` 曾遮蔽 Python 标准库，导致 PDF 库导入失败，这不表示 PDF 本身损坏。
