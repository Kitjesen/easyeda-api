# 嘉立创 API 本地核验工具层

2026-09-07，v0.1。用于当前已安装的官方 API Gateway / Bridge；没有替换嘉立创客户端，也没有修改官方闭源 API 内核或正在运行的桥接服务。

2026-09-08 兼容性补充：现已通过官方 Bridge 1.1.28/ws 8.21.3 的实际保存及独立回读验证，11 项工具测试通过。本核验层代码保持不变；新版 Bridge 保留本地连接限制并增加可查询版本信息。历史工作区的 `../official-skill` 指向全局已注册 Skill；本独立仓库的同名目录由安装器生成，见根目录 README。后文关于核验层没有替换 Bridge 的表述描述其自身职责，不表示当前服务仍为旧版。

## 已实现

- 自动扫描本机 49620–49629，核对 easyeda-bridge 身份；要求唯一连接窗口，桥接有未完成请求时停止。
- 每次请求前后核对工程 UUID、目标图页 UUID 和原理图类型。
- 所有经本工具提交的操作使用文件锁串行执行；不会锁住用户界面或其他外部脚本。
- 写前保存当前图页完整源码、脚本哈希和计划；可选 expectedBeforeSha256 拒绝过期计划。
- 写入与核验分成独立请求。写入不自动重试；核验最多读取三次，以处理已观察到的缓存滞后。
- HTTP 错误、脚本返回 error、核验不通过，均返回非零退出码并记录 unverified/rejected，不误报完成。
- geometry.mjs 将路径变为独立正交线段，去掉零长段和完全重复段，拒绝斜线；covered() 能识别被编辑器拆分/合并后的线段，便于根据实际状态恢复中断操作。
- source.mjs 保留原有换行、每条记录分隔符及删除记录。特别保留末条记录可能没有竖线的格式，修复了本次整体平移时源码被拒绝的问题。

## 调用

```powershell
node eda-verified/cli.mjs read can-read-plan.json
node eda-verified/cli.mjs apply operation-plan.json
```

计划里的 script、verifyScript 和 output 相对计划文件所在目录解析。apply 必须提供独立核验脚本，返回非空的 `{ok:true, checks:[{name:"...",pass:true}]}` 才判定成功。read 模式不会自动限制脚本内部能力，调用者必须只放只读脚本；这是本地开发工具，不能接收不可信脚本。

```json
{
  "name": "某个明确的原理图修改",
  "projectUuid": "精确工程 UUID",
  "pageUuid": "精确原理图页 UUID",
  "script": "apply.js",
  "verifyScript": "verify.js",
  "output": "result.json"
}
```

state/每次操作UUID/ 保存 before.json、脚本、结果、各次核验与最终 report.json。状态为 unverified 时先读取现有图，不能直接重复创建元件或导线。崩溃留下 operation.lock 时先核对记录里的 PID、请求状态与原理图，再人工恢复；不要盲目删锁。

## 已在实际工程中使用

本次 STM32G431 的 CAN 数字端接放置、PB10 标记处理、接线恢复、R6 身份恢复、模块整体平移及冗余 NET 标签清理均用此工具提交。完整电路、既有连接差分及原样工程导出另由 原硬件工作区的 `verify_can_termination.py`（未随本 API 仓库打包） 核验。

实际发现隐藏 NET 文字在导入后可能又显示。因此，本模块保留六个必需的跨块网络标签，内部短实线连接使用匿名网络；删除多余 NET 属性后核验引脚连接，而非仅把文字移到远处或设置隐藏。

## 能力边界

这层工具提供可审计的操作与核验，不是数据库事务，没有自动回滚，也不能强行解决客户端后台不刷新、PDF/SVG 超时或透明截图。图页源码备份不替代完整 epro2 备份。最终完成仍需原样工程导出、图面检查以及相应 PCB/固件/台架验证。

源码几何变更仍须核对实际引脚坐标和网表；软件检测不替代元件规格书和工程判断。该工具尚未注册成新的 MCP 服务，当前通过本地命令调用，并复用既有 Bridge。
